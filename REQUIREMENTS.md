# ResalePlatform — требования к проекту

Клон Авито: маркетплейс для продажи вещей между частными лицами.
Pet-проект для портфолио. Frontend: **React + TypeScript**, Backend: **ASP.NET Core Web API**.

---

## 1. Цель и рамки проекта

**Цель** — продемонстрировать fullstack-навыки: проектирование REST API, работа с БД,
аутентификация/авторизация, загрузка файлов, поиск и фильтрация, современный React-фронтенд.

**В рамках проекта (in scope):**
- Регистрация/вход пользователей
- Публикация, редактирование, удаление объявлений с фото
- Каталог с поиском, фильтрами, сортировкой, пагинацией
- Категории товаров
- Избранное
- Личный кабинет продавца
- Простой чат/сообщения между покупателем и продавцом (расширение)

**Вне рамок (out of scope, чтобы не растягивать):**
- Реальные платежи и эквайринг
- Доставка, логистика, трекинг
- Мобильное приложение
- Модерация с ML, антифрод
- Отзывы и рейтинги (можно добавить позже)

---

## 2. Роли пользователей

| Роль | Права |
|------|-------|
| **Гость** | Просмотр каталога и карточек объявлений, поиск, фильтры. Не может публиковать и писать сообщения. |
| **Пользователь** | Всё что гость + публикация/редактирование своих объявлений, избранное, сообщения, профиль. |
| **Администратор** | Управление категориями, удаление любых объявлений, блокировка пользователей. |

## 3. Функциональные требования

### 3.1 Аутентификация и профиль
- Регистрация по email + пароль.
- Вход, выход. Аутентификация через **JWT** (access + refresh токены).
- Хэширование паролей (ASP.NET Identity / BCrypt).
- Просмотр и редактирование профиля (имя, телефон, город, аватар).
- Валидация: уникальный email, требования к паролю.

### 3.2 Объявления
- Создание объявления: заголовок, описание, цена, категория, состояние (новое/б.у.),
  город, до N фотографий, контактные данные.
- Редактирование и удаление своих объявлений.
- Статусы: `Черновик`, `Активно`, `Продано`, `Снято с публикации`.
- Просмотр карточки объявления со счётчиком просмотров.
- Список «Мои объявления» с фильтром по статусу.

### 3.3 Каталог, поиск и фильтры
- Список объявлений с пагинацией (server-side).
- Полнотекстовый поиск по заголовку и описанию.
- Фильтры: категория, диапазон цены, город, состояние.
- Сортировка: по дате, по цене (возр./убыв.).

### 3.4 Категории
- Иерархия категорий (родитель → подкатегории), минимум 2 уровня.
- Управление категориями — только администратор.

### 3.5 Избранное
- Добавление/удаление объявления в избранное.
- Список избранного в личном кабинете.

### 3.6 Загрузка изображений
- Загрузка нескольких фото на объявление.
- Хранение на диске (`wwwroot/uploads`) или в S3-совместимом хранилище (MinIO).
- Ограничения: формат (jpg/png/webp), размер файла, количество.
- Генерация превью (thumbnail) — опционально.

### 3.7 Сообщения (расширение / этап 2)
- Диалог между покупателем и продавцом в контексте объявления.
- Список диалогов, история сообщений.
- Реалтайм через **SignalR** (или простой polling для MVP).

### 3.8 Администрирование (расширение)
- Просмотр всех пользователей и объявлений.
- Удаление объявлений, блокировка пользователей.

## 4. Нефункциональные требования

- **Производительность:** ответ API < 300 мс на типовых запросах; пагинация на всех списках.
- **Безопасность:** JWT, HTTPS, хэширование паролей, валидация ввода, защита от IDOR
  (пользователь редактирует только свои объявления), rate limiting на аутентификацию.
- **Валидация:** на бэкенде (FluentValidation / DataAnnotations) и на фронте.
- **Обработка ошибок:** единый формат ошибок (ProblemDetails), корректные HTTP-коды.
- **Логирование:** structured logging (Serilog).
- **Документация API:** Swagger / OpenAPI.
- **Адаптивность:** фронтенд корректно работает на desktop и mobile.
- **Тесты:** unit-тесты на бизнес-логику, интеграционные на ключевые эндпоинты.

## 5. Технологический стек

### Backend
- ASP.NET Core Web API (.NET 9), C#
- Entity Framework Core + **PostgreSQL** (Npgsql)
- ASP.NET Core Identity + JWT
- FluentValidation, Serilog, AutoMapper, MediatR
- Swagger (Swashbuckle)
- Архитектура: **Clean Architecture** — Domain / Application / Infrastructure / API, CQRS + MediatR

### Frontend
- React 18 + TypeScript, Vite
- Роутинг: React Router
- Состояние/данные: **TanStack Query** (server state) + Zustand/Context (UI state)
- Формы: React Hook Form + Zod
- HTTP: Axios (с интерсептором для refresh-токена)
- UI: Tailwind CSS
- Тесты: Vitest + React Testing Library

### Инфраструктура (по желанию, плюс к портфолио)
- Docker + docker-compose (API + БД + фронт)
- CI: GitHub Actions (build + test)
- Деплой: Render / Railway / Fly.io / VPS

## 6. Модель данных (основные сущности)

- **User** — Id, Email, PasswordHash, Name, Phone, City, AvatarUrl, Role, CreatedAt
- **Category** — Id, Name, Slug, ParentId (nullable)
- **Listing** (объявление) — Id, Title, Description, Price, Condition, Status,
  City, CategoryId, UserId, ViewsCount, CreatedAt, UpdatedAt
- **ListingImage** — Id, ListingId, Url, IsPrimary, SortOrder
- **Favorite** — Id, UserId, ListingId, CreatedAt
- **Conversation** — Id, ListingId, BuyerId, SellerId, CreatedAt *(этап 2)*
- **Message** — Id, ConversationId, SenderId, Text, IsRead, CreatedAt *(этап 2)*

## 8. Этапы разработки (roadmap)

**Этап 0 — Каркас.** Solution + структура проекта, БД + первые миграции, Swagger, базовый React-скелет с роутингом.

**Этап 1 — MVP (ядро):**
1. Аутентификация (register/login/JWT/refresh)
2. Категории (seed)
3. CRUD объявлений + загрузка фото
4. Каталог с поиском/фильтрами/пагинацией
5. Личный кабинет: мои объявления, профиль
6. Избранное

**Этап 2 — Расширения:**
7. Сообщения (SignalR)
8. Админ-панель
9. Отзывы/рейтинги (опционально)

**Этап 3 — Полировка:**
10. Тесты, Docker, CI/CD, деплой, README с демо.
